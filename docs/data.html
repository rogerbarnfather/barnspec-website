Where your data lives

One folder, in your project, committed with your code.

Barnspec keeps everything in the project’s barn: a project whose root holds a .barn/ folder. It finds the barn from any folder inside it, and writes nothing anywhere else. Without a barn it refuses to read or write, and barnspec init makes one.

What is in it #

.barn/barnspec/areas-of-business/   one file for each area of business, with its roles, stories and building blocks
.barn/barnspec/scenarios/           each area of business's Scenarios
.barn/barnspec/work/                each area of business's tickets
.barn/barnspec/settings.json        where generated Ports go (you create this)
.barn/barnspec/refinements/         unfinished refinements saved from the browser app

Commit .barn/ with your code. The files are JSON and are not meant to be edited by hand: use the commands or the browser app.

Start over #

wizard-reset shows what it would remove. Nothing is deleted until you add --force.

$ vendor/bin/wizard-reset
Barn: …/hotel
[dry run] would remove …/hotel/.barn/barnspec/areas-of-business (2 file(s))
[dry run] would remove …/hotel/.barn/barnspec/scenarios (1 file(s))

Dry run: nothing was deleted. Run again with --force to delete it.

Warning. wizard-reset --force deletes everything Barnspec has captured in the barn, and it cannot be undone. Commit first.
